Identifying the Problem Type

Problem TypeKeywords / clues
Shortest Path
(Dijkstra's Algorithm)		Moving efficiently between two specific locations — "shortest route," "minimum travel time," "least distance between X and Y"
Minimum Spanning Tree
(Prim's Algorithm)		Linking an entire network for minimum total length/cost — "connect all locations," "minimum total length of cable," "link all towers," always undirected
Network Flow
(Max Flow / Min Cut)		Maximum throughput or a bottleneck, always with a Source and Sink — "capacity," "bottleneck," "minimum cut," "source," "sink"
Allocation
(Hungarian Algorithm)		Pairing resources to tasks 1-to-1, minimising/maximising total — "assigning workers to jobs," "matching resources to tasks"
Scheduling
(EST/LST, Crashing)		Project timelines and completion time — "earliest/latest start time," "critical path," "float/slack," "crash," "minimum cost to reduce by X weeks"

Quick Tips

  • Shortest Path: trace the route back from destination to origin to confirm the exact path; write totals at each node rather than guessing from single edges.
  • Minimum Spanning Tree: apply the $V - 1$ rule ($V$ vertices need exactly $V - 1$ edges); never add an edge that creates a cycle, even if it's the shortest available.
  • Network Flow: only add capacities of edges crossing from the source side to the sink side (no backward edges); check the cut fully separates source from sink.
  • Allocation: for maximisation problems, subtract every entry from the largest value in the matrix before doing row/column reductions.
  • Scheduling (EST/LST): "Max Forward, Min Backward" — take the highest incoming total for EST, the lowest outgoing value for LST. Float = LST − EST.
  • Crashing: reducing a critical activity can shift the critical path — recalculate all path lengths after every reduction step.
Before you start a question Identify the problem type first using the keywords above — the method you use depends entirely on getting this right.
